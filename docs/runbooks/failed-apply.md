# Невдалий apply або recovery

1. Збережіть каталог deployment, state та приватні докази операції.
2. Прочитайте загальний status і окремий recovery.status.
3. Якщо recovered — попередній образ і health перевірено, але розгортання все одно невдале.
4. Якщо manual-attention або recovery-failed — встановіть фактичний стан Lambda,
   ECR, API, state та інших частково змінених ресурсів. Не видаляйте state.
5. Після усунення причини створіть новий план і перегляньте всі зміни.

Старий план не запускається вдруге. Ручний `--stage rollback` також вимагає
наявної справної функції для планування; якщо вона несправна і автоматичне recovery
не завершилося, потрібне окреме ручне відновлення з аналізом доказів.
Відкат образу не скасовує всі інфраструктурні зміни невдалого apply.
