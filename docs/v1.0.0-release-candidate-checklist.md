# v1.0.0 Release Candidate Checklist

The release procedure is maintained in [Release checklist](release-checklist.md).
The authoritative bundle schema is [Single-operator release evidence](single-operator-release-evidence.md).
This page summarizes the decision gates without duplicating either procedure.

## Scope

Stable 1.0 targets local CLI and a single-operator dev lab in one AWS account.
Production/OIDC, independent review and a separate sandbox are experimental
integrations. Windows/WSL2 support is unverified. Keep candidate results outside
Git; a completed test of another commit does not accept the release candidate.

## Compatibility Verification Pass

Use the matrix in [Distribution and compatibility](distribution.md#compatibility-matrix).
Both macOS and Debian transcripts must show candidate identity, installation,
menu/demo/completion and passing tests, including installer failure recovery.
Record actual architecture and tool versions. CI supplements these records.

## Documentation Audit

Check the [documentation index](README.md), first-run commands, image boundaries,
upgrade/recovery steps, limitations and links. Keep command behavior in
`devsecops inventory --format json` aligned with the stability contract.

## Security Review

Require behavioral regression coverage for config/schema refusal, signed HTTP,
plan binding, IAM/account boundaries, recovery, state readback and teardown.
Review changes to workflows, scanner isolation and Terraform permissions even
when production integration remains outside the stable scope.

## Blocker Register For v1.0.0 Stable

These are requirements for each candidate, not a live status report.

| Gate | Required evidence |
| --- | --- |
| RC-B1 · Lab lifecycle | Fresh A, B, failed C/automatic B, manual A; signed health, logs, live digest and state agree. |
| RC-B2 · Identity | Same clean commit, successful CI, installed wheel, source fingerprint and checksummed raw operations. |
| RC-B3 · Platforms | Both declared platforms pass installation, local operation and upgrade/failure recovery. |
| RC-B4 · Cleanup | Archives/restore verified; saved destroy plan applied; exact resource absence, KMS schedule and billing follow-up recorded. |

## Release Decision

Run `devsecops criteria --strict --format json` with the candidate evidence,
GitHub verification and accepted artifacts as shown in the release checklist.
Publish only after the owner authorizes that accepted candidate. Version 1.0
has not been released merely because this checklist exists or a gate passes.
