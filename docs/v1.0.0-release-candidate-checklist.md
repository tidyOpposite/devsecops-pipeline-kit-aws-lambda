# v1.0.0 Release Candidate Checklist

Current source: `0.16.0b2.dev0` (unpublished). Published prerelease:
`0.16.0b1` (`v0.16.0-beta.1`). Stable scope is local CLI and single-operator dev lab in one AWS account.
Production integrations remain experimental; lab evidence makes no production claim.
Previous published baseline: `v0.15.0`.

This is a maintainer guide to the evidence required for a stable release.
It contains requirements, not a transcript or a claim that checks passed.
Store candidate-specific results, timestamps, run IDs and logs outside Git in
`dist/devsecops/production-evidence/<version>/` (the legacy directory name also accepts scoped lab bundles) or `docs/local/`.

Prereleases may be published for testing before cloud acceptance. Do not mark
`v1.0.0` stable until every applicable gate below has passed for the same
reviewed commit and wheel. Never replace existing tags or release assets.

## Required Evidence Bundle

Attach or link these files from the release record:

| Evidence | Command or source |

| CLI unit, golden, E2E, and documentation tests | `PYTHONPATH=cli python3.14 -m unittest discover -s cli/tests` |

| Installed CLI smoke | `python3.14 -m pip install --no-deps --no-build-isolation .` then `devsecops --version` |
| Stable command inventory | `devsecops inventory --format json` and `devsecops inventory --status stable --format markdown` |
| Config schema contract | `devsecops config schema --format json` and `devsecops config schema --format markdown` |
| Strict config/readiness evidence | `devsecops config validate --strict --format json` and `devsecops status --strict --format json` |
| Generated artifact dry run | `devsecops generate --dry-run` |
| Audit evidence | `devsecops report --format json` |
| UX next-action evidence | `devsecops status --format json` |
| Version 1.0 criteria gate | `devsecops criteria --strict --format json` |
| Local RC evidence bundle | `devsecops evidence collect --rc` |
| Terraform format/init/validate | `terraform -chdir=terraform fmt -check -recursive`, `terraform -chdir=terraform init -backend=false -input=false -no-color`, `terraform -chdir=terraform validate -no-color` |
| Production walkthrough bundle | [Production deployment evidence](production-deployment-evidence.md) |
| Published release artifact proof | [Release checklist](release-checklist.md) section 6 |

The supported matrix is documented in
[Distribution and compatibility](distribution.md). The release candidate
record must show one evidence source for each row.

| Component | Supported target | Required evidence |
| --- | --- | --- |
| Ubuntu Linux | Ubuntu 22.04 LTS and 24.04 LTS on x86_64 or arm64 | GitHub Actions CI logs for unit/golden/E2E/package/install and Terraform checks. If `ubuntu-latest` changes, record the actual runner image from the workflow log. |

## Blocker Register For v1.0.0 Stable

Close these gates in the candidate acceptance record before tagging a stable
`v1.0.0`. Keep the record and collected logs outside Git; this public checklist
defines the requirements for every candidate.

| ID | Blocker | Required closure evidence |
| --- | --- | --- |
| RC-B1 | Candidate AWS lab lifecycle is unverified. | Fresh A, B, failed C/automatic B, manual A, logs, signed health and state, from one commit/wheel. |
| RC-B2 | Candidate package/source/CI identity is unverified. | Successful candidate CI, wheel SHA-256, source fingerprint and checksummed raw operations. |
| RC-B3 | Declared platform compatibility is unverified. | Candidate install, demo, completion, tests and upgrade/failure recovery on each declared platform. |
| RC-B4 | Candidate lab cleanup/retention is unverified. | Independent archive/restore, reviewed destroy, exact physical inventory readback, retained local state, KMS schedule and explicit billing follow-up. |

The [single-operator release contract](single-operator-release-evidence.md)
is normative for stable 1.0. Existing production/security tables describe
experimental integration review, not extra stable lab gates. Production proof
requires its original reviewer/OIDC/separate-account protections and can be
checked separately with `criteria --scope production`.

Run this command before any stable tag decision:

```bash
devsecops criteria --strict --format json
```

By default it checks `dist/devsecops/production-evidence/v<CLI version>`
(currently `v0.16.0b1`). For the
final stable record, pass the evidence directory that contains the completed
production walkthrough and supported-platform transcript:

```bash
devsecops criteria --strict --evidence-dir dist/devsecops/production-evidence/v1.0.0
```

## Release Candidate Decision

Prepare the next candidate after remaining audit fixes, local tests, package build,
Terraform validation, documentation audit, and security review pass. A stable
`v1.0.0` release must additionally close every blocker above and attach the
final evidence bundle to the release record.
